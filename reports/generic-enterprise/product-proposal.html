A Monday Morning Without Memory

Meet Martín Díaz — and the problem AMG was built to solve.

It is 9:14 AM on a Monday. Martín Díaz, Data Engineer on the ADO squad, sits down to build a new agent. His goal is simple: an assistant that helps his team find the right dataset owner when something breaks in production. The data catalog has the answers — he just needs the agent to find them reliably.

He wires the agent to the GenAI Gateway and runs his first query: "Who owns the flight punctuality dataset and what's the refresh schedule?" The agent replies with a name and a schedule. Sounds right. Martín uses it to route an incident ticket.

Two hours later, the ticket bounces back. Wrong owner. The dataset was transferred to a different squad three months ago, but the agent had no way to know — it started with zero context, scraped the catalog on the fly, and returned a stale result. No memory, no continuity, no audit trail.

The cold start problem — measured:
  • 45 minutes of Martín's time re-explaining context to the agent across three separate sessions that week
  • 4,200 tokens spent per session on re-loading background knowledge the agent already retrieved the day before
  • 1 misrouted incident because the agent returned a stale fact with no confidence signal or timestamp
  • Zero audit trail — no way to know where the wrong answer came from or which call triggered it

The Same Monday, With AMG

With Agent Memory Graph, Martín's agent starts differently. When it receives the ownership query, the MindMap pipeline fires: it mines the entity "flight punctuality dataset" from the prompt, traverses the Semantic graph, and retrieves 12 facts — including the current owner, the transfer event, the refresh schedule, and the last quality score — all with confidence weights and timestamps. The facts are serialized with unique IDs and injected into the synthesis prompt. The agent cites fact-id: f_7a3c as the source of the ownership answer.

The answer is correct. The transfer is reflected. The incident is routed in 90 seconds. The audit log shows exactly which fact the agent relied on, when it was last validated, and what its confidence weight was at query time.

With AMG — same query, different outcome:
  • 12 facts retrieved in under 5ms — pre-weighted, pre-validated, with provenance
  • 1,200 tokens used at synthesis — only the high-confidence, relevant facts were included
  • Correct owner returned — the transfer event had been ingested from DataHub and weighted appropriately
  • Full audit trail — every access, every fact cited, every authorization decision logged immutably

Martín did not change how he wrote the agent. He did not add prompt engineering or manual context loading. AMG handled it at the infrastructure layer — transparently, deterministically, and with zero hallucination risk.

That is what AMG gives your organization: a persistent, shared, auditable memory layer that transforms every AI agent from a stateless call into a context-aware, evidence-grounded workflow participant.

1. Executive Summary

Agent Memory Graph (AMG) is an enterprise-grade, GCP-native AI agent coordination platform that solves the most critical failure modes of production AI deployments: context loss, hallucination, and uncontrolled inference cost. Its two core innovations — the MindMap reasoning pipeline and the Cognitive Weighting system — work together to deliver measurably better AI: lower hallucination rates, faster retrieval, and significantly reduced LLM token consumption compared to conventional RAG architectures.

The MindMap pipeline (inspired by the ACL'24 research paper by Wen, Wang & Sun) forces every agent response to be built exclusively from graph-retrieved evidence. The Cognitive Weighting system (inspired by Engram's provable memory infrastructure) assigns Bayesian confidence scores to every fact in memory, applies temporal decay to stale knowledge, and gates synthesis on freshness and confidence thresholds. The practical result: agents retrieve only high-signal, recent facts; unused or contradicted facts fade out automatically; and token context is kept bounded and relevant — avoiding the sprawling, expensive context windows typical of naive RAG.

For your organization, AMG is the persistent coordination layer for your AI infrastructure: a shared memory fabric that all agents — from internal engineering copilots to customer-facing chatbots — can trust and reason over. AMG is production-ready (v0.2, 843 tests passing, P99 < 5ms), deploys within your existing GCP organization, and integrates naturally with your GenAI platform, data catalog, and service management tools.

Key numbers: P99 latency < 5ms (10x below SLO). Cognitive weighting bounds retrieval context to only high-confidence facts — directly reducing LLM token spend per agent turn. Grounding rate: 100% of responses backed by evidence or explicit insufficiency (zero hallucination).

2. Product Description

What It Does

Agent Memory Graph is a deterministic, grounding-first memory system for coordinating multiple AI agents within a single enterprise. It eliminates hallucination by forcing every agent response to be derived from evidence retrieved from a graph database. It preserves organizational context across sessions, users, and agents. And it provides immutable audit trails for every reasoning step — critical for regulated industries and compliance-sensitive workflows.

Problems It Solves

Enterprise AI deployments fail for consistent, well-understood reasons. AMG addresses each one with a specific architectural decision — not a workaround:

Problem How AMG Fixes It Key Feature
Context Loss — agents forget interactions across sessions; users re-explain problems repeatedly Context tier stores full session history; Semantic tier persists organizational facts indefinitely; recall is automatic on every agent turn Tripartite Memory Model
Hallucination — agents invent facts not grounded in organizational data MindMap pipeline: synthesis is prohibited unless facts are retrieved and serialized first. No evidence = explicit insufficiency signal MindMap Grounding Pipeline
High Token Cost — naive RAG floods context with loosely relevant chunks Cognitive Weighting filters retrieval to only high-confidence, fresh facts before synthesis. Bounded traversal prevents context sprawl Cognitive Weighting (Bayesian)
Low Retrieval Accuracy — vector similarity returns topically similar but factually unreliable chunks Graph traversal over Semantic tier follows typed relationships between entities, producing structurally grounded paths Spanner Graph Retrieval
Auditability Gap — no reasoning traces; impossible to debug decisions or prove compliance Audit tier logs every memory access, tool call, authorization decision, and reasoning step immutably (append-only, never deleted) Immutable Audit Trail
Multi-Agent Coordination Breakdown — multiple agents make conflicting decisions with no shared context All agents share the same Semantic graph. Contradiction detection flags conflicting facts before synthesis Shared Org Memory + Contradiction Detection

What AMG Provides

  • Tripartite Memory Model — Strict separation of Context (user-specific session history), Semantic (durable organizational facts with Bayesian confidence), and Audit (immutable compliance logs).
  • MindMap Reasoning Pipeline — A deterministic four-stage pipeline: Mine → Aggregate → Serialize → Synthesize. Every response is built exclusively from retrieved graph evidence.
  • Cognitive Weighting System — Bayesian log-odds weights on every node and edge, temporal decay for stale facts, confidence + freshness gating on synthesis.
  • Multi-Agent Coordination — All agents share the same Semantic memory graph. Coordinated, non-redundant operations with contradiction detection.
  • Immutable Audit Trail — Every access, tool call, and reasoning step in the Audit tier (append-only) for full compliance traceability.
  • ABAC Governance — Fine-grained authorization controls scope which agents can access which subgraphs and tiers. Deny-by-default with audited reason codes.
  • Document Extraction Pipeline — Ingest PDFs and PowerPoint files, extract entities, deduplicate, and populate the Semantic graph automatically.

3. Architecture Brief

AMG is a GCP-native Python service built on FastAPI, deployed on Cloud Run, backed by Google Cloud Spanner Graph for the memory store. All components are containerized and managed through Terraform infrastructure-as-code. The system deploys as a dedicated single-organization service within your GCP project — no data ever leaves your environment.

Memory Tiers

AMG divides all knowledge into three strictly isolated tiers with different retention policies, mutability rules, and access controls. The design mirrors human memory architecture: working memory (Context), long-term memory (Semantic), and autobiographical log (Audit).

Tier Scope & Owner What It Stores Lifecycle
CONTEXT Per user / per session User-specific conversation turns, agent responses, session state, intermediate reasoning. Scoped strictly to one session and one user — no cross-user sharing. 24–48 hours (rapid Bayesian decay on idle sessions)
SEMANTIC Organization-wide Durable facts, entity relationships, discovered insights, ingested document knowledge. Shared across all agents in the organization within ABAC policy scope. Months to years (slow decay; Bayesian reinforcement on repeated access)
AUDIT Permanent / compliance Every memory access, tool call, authorization grant/deny, reasoning step, and orchestration trace. Indexed with reason codes. Permanent retention (append-only, never modified)
Privacy note: The Context tier is the right home for any user-identifiable data in agent interactions (customer IDs, employee IDs, session content). Its 24-48h decay and strict per-session scope mean personal data is not persisted indefinitely — aligned with data minimization principles.

MindMap Reasoning Pipeline

The MindMap pipeline is the core reasoning engine of AMG. It enforces a strict evidence discipline: no LLM generates answers directly from user input. Every response passes through four deterministic stages:

Stage What It Does Output
1. Mine Extracts structured intent and named entities from the agent request. Identifies query anchors for graph traversal. Entity list + intent classification
2. Aggregate Traverses the Spanner Graph from identified anchors. Bounded traversal depth and cognitive weight thresholds filter out stale or low-confidence paths. Only ABAC-permitted subgraphs are accessed. Evidence path set (typed graph traversal results)
3. Serialize Converts graph paths and edges into canonical, traceable fact payloads. Each fact receives a unique ID for citation in the final response. Provenance (source node, edge type, confidence score) is preserved. Serialized fact payload with fact IDs
4. Synthesize Generates the agent response ONLY from the serialized fact payload using the configured LLM. Freshness and confidence gates are checked before synthesis. If no facts exist or confidence is below threshold, returns an explicit insufficiency signal — never guesses. Grounded response or explicit insufficiency
Grounding validation: After synthesis, AMG verifies that every claim in the response references a fact ID present in the serialized evidence. Any claim referencing an unknown fact ID causes the response to fail closed — a hard guarantee against hallucination.

Cognitive Weighting System

The Cognitive Weighting system gives AMG its ability to deliver high-accuracy retrieval at low token cost. Every node and edge in the memory graph carries a LogOddsWeight that evolves through:

Mechanism Formula / Rule Effect
Initial weight LogOddsWeight = 0.5 (62% confidence baseline) New facts enter with moderate confidence — not assumed fully reliable.
Bayesian reinforcement Weight += ln(1.25) ≈ +0.22 bits per successful access Frequently retrieved facts gain confidence automatically. High-signal knowledge rises to the top of traversal results.
Temporal decay Weight(t) = Weight(0) × e^(−0.05 × hours_since_access) Unused facts fade out. A fact at weight 2.73 after heavy use decays to near-zero after one week without access.
Pruning threshold Weight < 0.30 → soft-deleted from active traversal Stale, low-confidence facts stop polluting retrieval results without a hard delete.
Contradiction detection On ingest, conflicting facts are flagged with a tension marker Synthesis is gated: contradicted facts surface as ambiguous, not authoritative.
Freshness gating Synthesis checks average_freshness of evidence set against freshness_threshold Responses explicitly signal when evidence is stale — preventing overconfident answers from outdated knowledge.
Business impact: Instead of sending hundreds of loosely relevant RAG chunks to the LLM, AMG sends only the high-confidence, fresh, weighted facts that passed all filters. This bounds the synthesis context window, reduces LLM token consumption per agent turn, and raises answer accuracy.

Deployment Model

AMG is deployed as a dedicated single-organization service within your GCP organization. All agents in the organization share memory within the same company_id context. There is no multi-tenancy — data never leaks across organizations. The deployment follows a three-environment strategy managed through Terraform workspaces:

  • Development — Agent integration testing, API wiring, schema validation, first squad onboarding.
  • Integration (INTG) — Chaos engineering, load testing (7,500+ req/sec target), cross-tenant isolation validation, compliance documentation review.
  • Production — Canary deployment (5% traffic) → 24h monitoring → full traffic. Rollback time: < 5 minutes to previous version.

4. Strategic Value

Your organization has invested significantly in modern AI and data infrastructure. AMG is the missing coordination layer that makes these investments compound: every agent improves the shared memory; every team benefits from what others have learned.

The GenAI Ecosystem Today

From your GenAI platform, you operate a diverse model fleet (Claude, GPT-5, Gemini, Llama variants) — with per-user cost tracking and budget controls. You may also run quality feedback systems that enrich chatbot responses with human-validated knowledge. The platform demonstrates significant AI maturity.

However, these models are stateless: each call starts from scratch, with no shared context between agents, teams, or sessions. AMG directly addresses this gap — it is the persistent, shared memory layer that transforms isolated model calls into coordinated, context-aware, auditable agent workflows.

The Organizational Multiplier Effect

The compounding value of AMG grows as more agents and teams adopt it. Today each AI initiative operates in isolation — one domain's discovery goes unknown to others. AMG creates a shared organizational knowledge graph where every agent's findings enrich the corpus for all future agents.

Cognitive weighting ensures that the most frequently useful facts rise to the top automatically, while unused or contradicted knowledge decays — so the shared memory self-maintains without manual curation.

Compliance alignment: If you operate in regulated environments — aviation safety, financial reporting, data protection, healthcare — AMG's immutable AUDIT tier and ABAC controls provide the traceability and access governance required for AI use in safety-critical and compliance-sensitive decisions. No simple RAG or stateless chat stack provides this.

8. Recommendation & Next Steps

Agent Memory Graph is production-ready today. The recommended approach is to begin with a focused 4-week pilot led by your GenAI team on a single high-value, well-scoped use case — either an internal AI assistant or an operation-support tool. Both have clear data sources already cataloged, clear quality metrics, and limited customer data privacy implications, making them ideal for a first validation before expanding to external-facing chatbots.

Pilot Week-by-Week:
  • Week 1: Platform engineer deploys GCP dev environment; GenAI Gateway wired to AMG.
  • Week 2: GenAI team runs first agent interactions through the MindMap pipeline; validate grounding and audit trail completeness.
  • Week 3: Security/governance stakeholder reviews ABAC configuration and audit logs.
  • Week 4: Go/No-Go decision. If pass thresholds → proceed to full 16-week plan. If not → identify root cause and iterate before expanding.

The customer-facing use case — the highest-scale and highest-impact application — should enter the plan in Phase 2, after the internal pilot has validated the core pipeline and governance model. This sequencing manages risk while preserving the timeline for customer-facing value delivery.
