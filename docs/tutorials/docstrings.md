## How to write good docstrings?

**Guidelines**:

- **Public APIs**: Always document public functions and classes.
- **Complex logic**: Document non-obvious implementations.
- **Business logic**: Explain why decisions were made.
- **Simple getters/setters**: Documentation may be optional.

**Focus on**:

- **Purpose**: What does this function do?
- **Parameters**: What inputs does it expect?
- **Returns**: What does it return?
- **Side effects**: Does it modify state or have external effects?
